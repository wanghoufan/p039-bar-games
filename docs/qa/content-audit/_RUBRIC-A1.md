# 内容质量审查判定口径 v2（Phase A.1 校准版｜全批共用，务必逐字遵守）

你在审 Party Night V2 当前实际运行的 350 张主线题卡。目标：**如实判定每张题玩完之后，参与者到底多知道了这个人什么，以及它在现场起什么作用。**

用户真人试玩原话（标尺）：
> 整体非常无聊，很多题虽然形式上在互动，但玩完之后并没有真正增加彼此了解；缺少兴趣爱好、生活方式、恋爱观、择偶观、亲密/性观念、小癖好等真正有信息增量的内容。

## 输出格式（硬要求）

**JSON Lines：一行一个 JSON 对象。** 不要数组包裹，不要 Markdown 围栏（不要 ```），不要任何解释文字。行数必须与输入行数一致，cardId 与顺序必须与输入完全一致。`text` 照抄原文一字不改。

每行字段（顺序固定，全部必填）：

1. `cardId` 照抄
2. `gameType` 照抄
3. `text` 照抄
4. `semanticType` — 真人语义类型，6 选 1
5. `topic` — 信息主题，10 选 1
6. `infoGain` — 信息增量，高/中/低/0
7. `learned` — 玩完后新知道什么，一句大白话，具体到「知道了谁的什么」
8. `promotesUnderstanding` — 是/弱/否
9. `socialEnergy` — 现场能量，高/中/低
10. `relationshipProgression` — 关系推进度，高/中/低
11. `duplicateCluster` — 语义簇标签或 `-`
12. `verdict` — 保留/改写候选/删除候选

---

## 轴一：semanticType（真人语义类型，6 选 1）

- `自我披露`：主要让**说话的人讲自己**（自身经历、偏好、感受、过去）。
- `相互了解`：主要产出**关于对方/彼此的稳定个人信息**，双方真的交换了可复述的事实。
- `现场评价/猜测`：对在场某人**下评价、猜心思、投票、排名、指认**。即使形式是"让某人对某人说话"，只要落点是"大家觉得这人怎么样"而非"这人有什么"，就归这一类。
- `行动互动`：内容是一个动作（碰、换位、递东西、闭眼…），动作本身是全部内容。
- `暧昧推进`：明确朝男女关系升温（表态、择偶、亲密试探、表白、加码）。
- `纯看戏/低信息`：群体起哄、喊口号、纯热闹，跟具体人物信息挂不上。

## 轴二：topic（信息主题，10 选 1）

以「答完知道了什么」为准，不是题面字面。

`兴趣爱好`（具体爱好/兴趣/技能）｜`生活方式`（作息/居住/工作节奏/饮食/消费）｜`性格/习惯/小癖好`｜`择偶偏好/吸引力`｜`恋爱观`（对恋爱的态度、关系规则红线）｜`亲密/性观念`（亲密尺度、边界、暧昧容忍度）｜`边界/吃醋/异性朋友/前任`｜`人生价值/未来`｜`现场化学反应`（此刻这桌的临时状态，不构成稳定信息）｜`无明确人物信息增量`

## 轴三：infoGain（信息增量）— **本轮已校准，务必按新定义**

核心标准：**答完之后，参与者是否多知道了这个人的一件可复述的事。**

- `高`：**只要满足下面任一条即可判高**（不再要求必须是"每周三固定打羽毛球"这种硬事实）：
  - 得到一个**明确且稳定的偏好**（例：明确说自己"提前一周计划旅行，从不临时起意"）；
  - 得到一条**明确的关系规则/红线**（例：明确说"谈恋爱后不接受对方查手机"）；
  - 得到一个**明确的价值选择**（例：明确说"钱不重要，我更看重对方有自己热爱的事"）；
  - 得到一条**明确的边界**（例：明确说"绝对不能拿感情开玩笑""不喝酒"）；
  - 一次**明确且稳定的亲密态度**（例：明确说"暧昧可以，发生关系前一定会先确认"）；
  - 一个**具体经历及其原因**（例：因为他高三那年做过什么，导致他至今如何）。
  判高还要求：**答完之后现场的人能复述出来**，且换个局再问答案仍然成立。
- `中`：半稳定倾向、二元偏好、缺原因也缺具体例子，答案有一定稳定性但不够确定（例："他好像是计划型""她大概偏慢热"）。
- `低`：只有一次性的现场反应或临时情绪，换个局就作废（例："他被夸会笑""他今晚起哄最积极"）。
- `0`：完全不产生关于人的信息（纯群体起哄、纯道具动作、纯猜谁最X且无下文、纯喊口号）。

**校准提醒**：本轮刻意放宽了「高」。像"你怎么看更长期的关系""你希望对方怎么对你""如果只能选一个你选哪种人"这类，只要当事人给出了一个**明确的、站得住的、之后还能复述的答案**，就判**高**，不要因为"不够硬"而降为中。只有当答案本身是泛泛的二元对立（主动 vs 被动、直球 vs 慢热）且讲不出原因时才判中。

## 轴四：promotesUnderstanding（是/弱/否）

`是` 明确获得对方个人信息｜`弱` 有一点但不稳｜`否` 完全不产生人物认知。

## 轴五：socialEnergy（现场能量，新增，高/中/低）

衡量**这题在酒吧现场好不好用**，与信息量无关。高能量的题即使信息量为 0 也有保留价值（少量当调剂）。

- `高`：有明显笑点/热场效果，全场能笑、能起哄、能带出参与感或张力，适合真人酒吧现场。
- `中`：有一点互动趣味，不热场也不冷场，能正常玩完。
- `低`：尴尬、容易冷场、或者需要额外解释才成立，现场不好用。

## 轴六：relationshipProgression（关系推进度，新增，高/中/低）

衡量**这题是否推动两个人之间的事往前走**。

- `高`：明显帮助破冰、或暴露双方真实偏好、或产生暧昧张力、或形成一次真正的双向了解、或明确推动下一步（加微信/约下次）。
- `中`：有推进作用但不明显，属于常规互动。
- `低`：不推进关系，纯热闹或纯评价。

**严禁把「低信息」直接等同于「必删」**：低信息但 socialEnergy 高、relationshipProgression 高的题（例如某些让全场为一个猜测欢呼、指认后当场承认的题），verdict 应为**保留**。

## 轴七：duplicateCluster（语义簇标签或 `-`）

**重要口径**：这只是"把语义相近的题归进一个簇"，**不等于"这是重复题"**。判定重复至少要有 2 张同簇才算候选。给标签时用简短的英文 kebab 标签（如 `first-impression`、`who-more-attractive`、`shared-skeleton-act`），确实没有同簇就给 `-`。

## 轴八：verdict（保留/改写候选/删除候选）

现在**必须三轴合看**（infoGain + socialEnergy + relationshipProgression）：

- `保留`：三轴里至少有一轴是强项。
  - infoGain 高，或
  - socialEnergy 高且现场好用（少量调剂），或
  - relationshipProgression 高。
  infoGain 为中、另外两轴不弱的，也算保留。
- `改写候选`：三轴都偏弱（中/中/中以下），骨架可救、换个主题或换个对象能救活。
- `删除候选`：三轴全弱（infoGain 低或 0，且 socialEnergy 低，且 relationshipProgression 低），或纯凑数、纯重复、跟人物信息完全无关。

## 严禁犯的三个错

1. **严禁把「对在场某个人发表评价/猜测」自动算成「相互了解」。** 「谁最容易被异性搭讪」「TA给你的第一印象是什么」「谁最有吸引力」「谁最可能让人想继续聊」→ 一律 `现场评价/猜测`。
2. **严禁因为题面看起来像互动就给高增量。** infoGain 只看答完脑子里剩下什么。
3. **严禁为了显得严格就把本该判「高」的降成「中」。** 本轮「高」的门槛已经放宽，宁可判高也不要虚低；但也不许为了"让高>0"而放水——高必须真的能复述且换个局仍成立。

## 特别提示
- 「第一印象 / 注意谁 / 谁更有意思 / 谁想继续聊」这一族：几乎都是 `现场评价/猜测` + 低增量，但 socialEnergy 通常高（现场热闹）——这类 verdict 更可能是**保留**而非删除。
- 「我从来没有…」族：注意区分——逼当事人讲**自己具体经历或原因**的是好题；只是喊一句"有人吗"再起哄的是低增量。
- 「二选一」族：选项若是**当事人自己的明确偏好**（尤其带原因、带立场），可判高 infoGain。
- 「默契测试」族：先互猜、再本人公布答案——若公布的是**本人的明确答案**，infoGain 可判高。
- 「真心话」族：注意区分"讲自己"（自我披露）与"评价对方"（现场评价）。PN-TRUTH-001～005 这类"说说你觉得 TA ……"属后者。
